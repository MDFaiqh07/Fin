# FinTrack deployment (Render + MongoDB Atlas)

This project is configured as a **single Render web service**: Render builds the React/Vite client and Express serves both the API and the built client. MongoDB Atlas is the persistent database. Do not use a local MongoDB URI in a hosted deployment.

## Important data guarantee

The app's data lives in MongoDB, not in the deployed filesystem. Use a persistent MongoDB Atlas cluster and keep the same `MONGODB_URI` after deploys. Render redeploys then won't erase users or financial records. Back up the Atlas database before changes. Never run the demo seed again after users start editing, because it intentionally replaces Lily and Noah's demo records.

## Deploy

1. Push the contents of this `FinTrack` folder to a private GitHub repository.
2. Create a MongoDB Atlas cluster/database. Create a database user and allow network access from Render (for a quick demo, Atlas allows `0.0.0.0/0`; prefer tighter network controls when possible). Copy the `mongodb+srv://...` connection string and include database name `fintrack`.
3. In Render, choose **New → Blueprint**, connect the repository, and select `render.yaml`.
4. Fill the prompted secrets in Render environment settings:
   - `MONGODB_URI`: your Atlas URI
   - `ADMIN_PASSWORD`: a unique password at least 12 characters
   - `DEMO_USER1_PASSWORD`: desired Lily password (at least 8 characters)
   - `DEMO_USER2_PASSWORD`: desired Noah password (at least 8 characters)
   `JWT_SECRET` is generated by Render. Keep all secrets out of Git.
5. Deploy. Render builds the frontend and starts the API. Check `https://YOUR-SERVICE.onrender.com/api/health` for `{"status":"ok","service":"FinTrack API"}`.
6. Seed the accounts **once**, after the service is deployed. Open the Render service Shell and run:
   ```sh
   npm run admin:seed
   npm run demo:seed
   ```
   These commands use the same `MONGODB_URI` environment variable as the live service. The seed creates admin, Lily, Noah and 2,000 synthetic transactions plus budgets, goals, investments and bills. Do not run these commands again on a database containing edits you want to keep.
7. Sign in at `https://YOUR-SERVICE.onrender.com/login`.

## Demo login names

Use the passwords you set in Render environment variables:

- Admin username: `admin` (email `admin@fintrack.local`)
- Lily username: `lily` (email `lily@fintrack.local`)
- Noah username: `noah` (email `noah@fintrack.local`)

Passwords are not printed or hard-coded into the deployment guide. Change them via your environment/seed process before sharing the site. Since the seed scripts set the configured demo passwords, seed only once and store these secrets safely.

## Deploy to Vercel instead

This repository is designed first for Render because the Express server expects a long-running process and MongoDB connection. Vercel deployment requires converting the API entry point to serverless function semantics and configuring SPA rewrites; use Render for the lowest-error path unless you want a separate Vercel-specific adapter.

## Local development

Copy `server/.env.example` to `server/.env`, set `MONGODB_URI` and a strong `JWT_SECRET`, run `npm install`, then run `npm run admin:seed` and `npm run demo:seed` once. Start with `npm run dev` and visit `http://localhost:5173/login`.
